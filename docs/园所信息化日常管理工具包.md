# 园所信息化日常管理工具包｜模拟模板与操作规范

> **作品属性：模拟工具包。** 表格中的园所、设备、人员、编号和记录均为虚构示例，不对应真实机构或真实员工。正式使用前应按集团制度、资产分类、财务口径、数据安全要求进行调整。

## 一、工具包用途

面向幼儿园集团信息管理员日常工作，覆盖设备资产登记、故障报修、巡检、账号权限、数据备份、月度汇总和交接。核心原则是“一物一档、故障有单、处理有记录、权限有审批、备份可验证”。

### 3. Excel常用校验思路

- 资产编号唯一性：使用条件格式或 COUNTIF 检查重复编号。
- 设备状态：设置数据验证下拉选项，避免出现“使用中/在用/正常”等多个同义值。
- 保修提醒：用日期差计算距保修到期天数，提前 30 天提示；空值不参与提醒。
- 台账筛选：按园区、设备类别、状态、责任岗位筛选。
- 变更留痕：不要直接覆盖关键历史信息；设备调拨、维修、报废应记录日期、经办人和审批依据。

示例公式（假设保修到期日在 I2）：

```excel
=IF(I2="","未登记",IF(I2<TODAY(),"已过保",IF(I2-TODAY()<=30,"30天内到期","正常")))
```

重复资产编号检查（假设编号在 A 列）：

```excel
=COUNTIF($A:$A,A2)>1
```

## 三、设备报修与维修记录

### 1. 工单字段

| 字段 | 说明 |
|---|---|
| 工单编号 | 例如 FIX-2026-0001 |
| 报修时间 | 提交时间 |
| 报修园区/位置 | 精确到房间或区域，但公开展示时去标识化 |
| 报修设备编号 | 关联资产台账 |
| 故障现象 | 描述可复现现象，不写猜测结论 |
| 影响程度 | 高/中/低，由管理制度定义 |
| 优先级 | 紧急/高/普通 |
| 处理人 | 内部人员或服务商 |
| 处理过程 | 检查、定位、维修或更换情况 |
| 处理结果 | 已恢复/临时恢复/待配件/转外修 |
| 完成时间 | 实际完成时间 |
| 使用人确认 | 是否确认恢复 |
| 关联费用 | 按财务制度记录 |
| 附件 | 报修照片、维修单等，注意隐私 |

### 2. 工单状态流转

```text
待受理 → 已受理 → 处理中 → 待确认 → 已关闭
                    ↘ 待配件/外部维修
                    ↘ 暂停（注明原因与跟进时间）
```

关闭工单前至少确认：故障现象已记录、处理结果明确、使用人已确认或注明无法确认原因、资产台账状态已同步。

### 3. 虚构工单示例

| 工单编号 | 设备编号 | 故障现象 | 处理过程 | 结果 |
|---|---|---|---|---|
| FIX-2026-0001 | IT-XX-0002 | 打印任务进入队列但未输出 | 检查连接与队列，按授权流程重启打印服务并测试 | 模拟：恢复正常 |
| FIX-2026-0002 | IT-XX-0003 | 无线网络间歇中断 | 记录发生时段，检查设备状态与线路，提交网络服务商 | 模拟：待进一步观察 |

## 五、账号与权限管理

### 1. 基本流程

1. 申请人提交账号/权限申请，说明业务目的、系统范围和所需权限。
2. 部门负责人或系统责任人审批。
3. 管理员按最小权限原则开通，不共用个人账号。
4. 记录开通人、审批人、权限范围、开通时间和复核日期。
5. 调岗、离职、外包服务结束或业务变化时，按制度及时变更或回收权限。
6. 定期复核高权限账号和长期未使用账号。

### 2. 权限登记字段

| 字段 | 内容 |
|---|---|
| 账号标识 | 使用内部账号ID，公开文档不得放真实账号 |
| 所属园区/部门 | 业务归属 |
| 系统名称 | OA、邮箱、业务系统等 |
| 权限角色 | 普通用户、审核、管理员等 |
| 申请单号 | 对应审批记录 |
| 开通/变更/回收时间 | 完整生命周期 |
| 审批人 | 按制度授权 |
| 复核日期 | 定期检查 |
| 状态 | 有效/冻结/已回收 |

**安全要求：** 不在台账或公开仓库保存密码、验证码、密钥、恢复码；不通过聊天记录明文传递密码；管理员操作应使用独立账号并保留必要审计记录。

## 六、数据备份与恢复检查

### 1. 备份登记字段

- 系统/数据范围
- 备份任务编号
- 备份策略与周期
- 备份开始/结束时间
- 存储位置（内部受控记录，不在公开仓库披露）
- 执行结果
- 文件完整性校验结果
- 异常原因与工单编号
- 最近一次恢复验证时间
- 执行人/复核人

### 2. 备份检查流程

1. 检查任务是否按计划启动并完成。
2. 检查日志中是否出现错误、超时或空间不足。
3. 对备份文件进行完整性校验。
4. 按批准的恢复演练计划，在隔离或测试环境验证可恢复性。
5. 记录恢复验证结果、耗时、问题和改进措施。
6. 失败任务建立问题单，直到复核通过。

> 备份“显示成功”不等于数据一定可恢复。恢复验证应在授权的测试环境进行，严禁在生产环境进行未经批准的覆盖性操作。

### 3. Linux/MySQL日常检查命令示例

以下仅为授权环境中的只读检查示例，实际命令需按系统版本、账号权限和园所运维规范调整。

检查磁盘空间：

```bash
df -h
```

查看内存概况：

```bash
free -h
```

查看系统运行时间与负载：

```bash
uptime
```

查看 MySQL 服务状态（systemd 环境）：

```bash
systemctl status mysql
```

查看最近服务日志（需按发行版与服务名称调整）：

```bash
journalctl -u mysql --since "today" --no-pager
```

检查数据库连接与版本（使用已授权账号，不在命令中暴露密码）：

```sql
SELECT VERSION();
SHOW DATABASES;
```

### 月报文字模板

**一、本月工作概况**  
本月完成设备台账更新、日常巡检、故障受理与处理跟进、备份状态检查及账号权限变更登记。以上数据为演示数据，正式月报以实际系统记录为准。

**二、问题与风险**  
列出未关闭工单、重复故障、备份失败、设备过保、权限未复核等问题，并说明影响范围和当前状态。

**三、下月计划**  
明确待完成事项、责任人、计划时间和验收标准，例如完成指定园区设备盘点、完成备份恢复验证、关闭超期工单。

## 八、常用操作SOP

### SOP-01 新设备入库

1. 核对采购/调拨凭证及设备实物。
2. 登记唯一资产编号、型号、序列号和保修信息。
3. 记录园区、位置、责任岗位和启用日期。
4. 按园所制度完成基础配置与安全检查。
5. 由领用人确认，保存必要交接记录。
6. 更新资产台账并纳入后续巡检。

**验收标准：** 每台设备有唯一编号、有责任归属、有状态、有可追溯的入库/领用记录。

### SOP-02 故障受理与关闭

1. 记录报修人、时间、设备编号和故障现象。
2. 判断影响范围与紧急程度；影响教学或安全保障的事项立即按园方应急流程上报。
3. 建立工单并分派处理人。
4. 处理过程记录检查项、变更项和结果。
5. 由使用人确认恢复；无法恢复时说明替代方案和后续计划。
6. 关闭工单并更新资产状态。

**验收标准：** 工单信息完整、处理过程可追溯、结果有确认、未解决事项有跟进责任人。

### SOP-03 账号权限变更

1. 收到正式申请或人事/岗位变更通知。
2. 核对审批权限和申请范围。
3. 按最小权限原则变更账号。
4. 记录操作时间、操作人和审批依据。
5. 通知申请人验证业务可用性。
6. 按周期复核权限。

**验收标准：** 每次权限变化有审批、有记录、有复核，不保留离职人员不必要权限。

### SOP-04 备份失败处理

1. 记录任务编号、失败时间和错误信息。
2. 检查空间、网络、权限、服务状态等基础原因。
3. 按授权流程处理，不擅自删除历史备份或修改保留策略。
4. 重新执行任务并校验结果。
5. 按计划完成恢复验证。
6. 形成异常报告，必要时升级至系统供应商或上级技术人员。

**验收标准：** 失败有记录、处理有过程、结果有校验、恢复能力有验证。

## 九、交付验收清单

| 验收项 | 通过标准 |
|---|---|
| 资产台账 | 字段完整、编号唯一、状态规范、可筛选 |
| 报修工单 | 状态闭环、处理记录完整、未结事项可追踪 |
| 巡检记录 | 有日期、设备、检查项、结果和责任人 |
| 权限登记 | 有审批依据、最小权限、变更与回收记录 |
| 备份记录 | 有任务结果、异常跟进和恢复验证 |
| 月度报告 | 指标口径明确、数据可追溯、问题有计划 |
| 数据安全 | 不公开账号密码、儿童信息、内部网络和系统敏感配置 |

## 十、作品集真实性说明

本工具包为个人能力演示而制作，模板和样例数据均为虚构，不代表曾服务某家幼儿园或管理过真实集团设备。它展示的是可迁移的工作方法：台账设计、Excel数据整理、工单闭环、Linux基础巡检、MySQL基础检查、备份验证意识、权限管理和文档规范。正式岗位执行必须遵守雇主制度、授权范围和数据安全要求。
